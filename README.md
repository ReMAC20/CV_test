# Ориентация текста: 0° / 180°

Решение выдаёт вероятность `p_180` для каждого из 20 000 изображений. Готовый ответ - `submission.csv` с колонками `image_id,p_180`. Исходные данные не изменяются.

## Запуск

Python 3.10, команды из корня проекта (например терминал VS Code):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe predict.py
```

Изображения должны лежать в `test/images/`, шаблон - в `sample_submission.csv`.

## Модель и веса

Используется предобученный классификатор **PP-LCNet x1.0** из PaddleOCR. Он определяет ориентацию уже вырезанного текстового фрагмента: 0 или 180. Искать текст на фотографии и распознавать сами слова в не требуется.

Веса - параметры, которые модель получила при обучении авторами PaddleOCR. Я загрузил готовые ONNX-файлы и использовал их без дообучения. Файл ONNX содержит структуру сети и её параметры; ONNX Runtime выполняет вычисления локально на CPU.

| Файл в `models/` | Назначение |
|---|---|
| `lcnet_025.onnx` - 1,02 МБ | Более компактный вариант, использованный для сравнения на синтетике |
| `lcnet_100.onnx` - 6,78 МБ | Итоговая модель, которой рассчитан `submission.csv` |

Для обычного запуска нужен `lcnet_100.onnx`; второй файл нужен для повторения сравнения. Выбранная модель, температура **T=1,5** и использование двух ориентаций зафиксированы в `config.json`. Перед загрузкой модель проверяется по SHA-256.

## Пайплайн предсказания

1. **Чтение входов.** `predict.py` берёт идентификаторы и порядок строк из `sample_submission.csv`, находит соответствующие файлы в `test/images/`. Отсутствующие изображения и дубли идентификаторов вызывают ошибку.
2. **Подготовка двух ориентаций.** Кроп декодируется в RGB без автоматического поворота по EXIF. В памяти создаётся его копия, повёрнутая на 180; исходный файл не меняется.
3. **Предобработка.** Обе версии масштабируются до 160×80 без добавления полей. Значения пикселей делятся на 255 и нормализуются: `(x - mean) / std`, где `mean = [0.485, 0.456, 0.406]`, `std = [0.229, 0.224, 0.225]`. Каналы переводятся в порядок CHW, ожидаемый моделью.
4. **Инференс.** Изображения обрабатываются батчами по 64. Модель возвращает две вероятности после softmax; второй столбец - оценка поворота на 180. Для каждой исходной картинки выполняются два прохода: исходная и повёрнутая версии.
5. **Обработка вероятностей.** Применяется temperature scaling: `q_T = sigmoid(logit(q) / T)`. При T=1,5 прогнозы становятся менее уверенными; это значение выбрано на синтетической валидации. Затем ответы объединяются: `p_180(x) = (q_T(x) + 1 - q_T(R180(x))) / 2`. Вычитание из единицы переводит ответ для повёрнутой копии обратно к исходной ориентации. Получается согласованность `p_180(R180(x)) = 1 - p_180(x)`.
6. **Сохранение.** Проверяются диапазон [0, 1] и отсутствие NaN. Результат записывается в `submission.csv` в порядке шаблона, с восемью знаками после запятой. Время работы, параметры запуска и контрольная сумма CSV сохраняются в `reports/inference.json`.

Например, `p_180 = 0,9` означает высокую уверенность модели в повороте на 180°, а значение около 0,5 - неопределённость.

## Валидация и результат

Сравнивались x0.25/x1.0, один/два прохода и пять температур. Выбор сделан на 600 синтетических строках; проверка - на 400 других строках с отдельными шрифтом и словарём. Каждая строка даёт пару 0°/180°; seed - 42 и 2026.

Генератор `scripts/validate.py` использует русский и английский текст, цифры, шум, размытие, JPEG-сжатие и небольшой наклон. Метки известны из способа генерации. Настройки выбираются только на первой выборке; отложенная выборка используется для финальной проверки. Папка `assets/` содержит шрифты для генератора и их лицензии: для запуска `predict.py` она не нужна.

- **1 - Brier на синтетическом holdout: 0,9304**. Метрика скрытого теста неизвестна; результат на синтетике не гарантирует такого же качества на фотографиях.
- Полный расчёт: около **229 секунд**, CPU, 4 потока, batch size 64.
- Повторный запуск дал идентичный CSV; 7 тестов прошли, хеши исходных файлов совпали.

Дообучение, ручная разметка теста, LLM/VLM и внешние inference API не использовались. Подробные результаты и контрольные суммы - в `reports/`.

## Проверки и файлы

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/audit_data.py --verify
.\.venv\Scripts\python.exe scripts/check_submission.py
```

Основной код - `predict.py` и `src/orientation.py`. Повторить подбор на синтетике: `python scripts/validate.py` (перезапишет `config.json`). Для проверки воспроизводимости запустите `python predict.py --output reports/reproduced.csv`, затем `python scripts/check_submission.py --compare reports/reproduced.csv`. Побайтовое совпадение проверено в одинаковом CPU-окружении; на других платформах возможны численные различия.

Архив для GitHub - `dist/text-orientation-solution.zip`; пересборка: `python scripts/package_solution.py`. Он содержит код, веса и результаты, но не исходные данные и `.venv`. На платформу сдаётся `submission.csv`, ссылка на репозиторий - отдельно.

## Источники

Модель - [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR), ONNX-веса - [RapidOCR](https://github.com/RapidAI/RapidOCR), артефакты v3.9.2 (Apache-2.0). Версии и SHA-256 - `models/manifest.json`. Библиотеки: ONNX Runtime, NumPy, OpenCV, Pillow. Шрифты синтетики: Noto Sans, Noto Serif и Roboto Mono из [Google Fonts](https://github.com/google/fonts), SIL OFL. Лицензии приложены в `models/` и `assets/`.
